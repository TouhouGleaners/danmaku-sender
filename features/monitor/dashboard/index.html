    实时存活率仪表盘

    弹幕监视器用于在发送完成后追踪弹幕的存活状态。它会定时向 B 站弹幕池 API 查询当前视频上可见的弹幕，与已发送记录进行比对，帮你识别被系统拦截的「幽灵弹幕」。

    启动监视

    切换到侧边栏的「弹幕监视器」页面，点击 [监视队列] 按钮。

    启动条件：

    • 队列中至少有一个任务。
    • 已配置有效的 B 站登录凭证（SESSDATA）。

    启动后，按钮变为 [停止监视]，监视器开始按设定的轮询间隔定期查询。

    整体统计仪表盘

    页面中部是四个大数字卡片，实时显示当前队列的整体统计：

    卡片 含义 颜色
    已发送 (Total) 本次统计范围内已发送的弹幕总数 深色
    已存活 (Verified) 已确认在 B 站弹幕池中可见的弹幕数 绿色
    待验证 (Pending) 已发送但尚未在弹幕池中找到的弹幕数 橙色
    疑似丢失 (Lost) 经过多轮查询仍未在弹幕池中出现的弹幕数 红色

    关于「待验证」和「疑似丢失」

    「待验证」不代表弹幕一定丢失——B 站的弹幕审核可能需要几分钟到几小时。只有经过多轮查询（跨越较长时间窗口）仍未出现时，才会被标记为「疑似丢失」。

    队列任务表格

    页面顶部是一个任务表格，显示当前队列中每个任务的独立统计：

    列 说明
    任务标识 BV 号 + 分 P 信息
    已发送 该任务的发送总数
    已存活 该任务中已确认存活的弹幕数
    待验证 该任务中尚未验证的弹幕数
    疑似丢失 该任务中疑似丢失的弹幕数

    每个任务的统计数据独立计算，方便你定位是哪个分 P 出了问题。

    统计基线

    统计基线决定了「统计范围内」的时间窗口——只统计该时间点之后发送的弹幕。

    基线选项 说明
    本次启动后 只统计本次程序启动后发送的弹幕（默认）
    最近 24 小时 只统计最近 24 小时内发送的弹幕
    全量历史 统计数据库中所有历史记录

    此外，点击 [设为当前] 按钮可以将基线重置为当前时间，适用于「我只想看从现在开始的这批任务」的场景。

    多批次对账

    如果你分多批发送弹幕（例如上午一批、下午一批），可以在每批开始前点击「设为当前」，这样监视器只统计当前批次的存活率，不会被之前批次的数据干扰。

    轮询间隔

    控制监视器多久向 B 站弹幕池查询一次。

    配置项 范围 默认值
    refresh_interval 10 ~ 3600 秒 60 秒
    • 间隔越短，发现存活/丢失的速度越快，但 API 请求频率也越高。
    • 建议保持默认的 60 秒，除非你需要实时追踪。

    监视日志

    页面底部是日志面板，显示每轮核销后的汇总信息：

    统计(基线 09-10 14:30): 已发 156 / 存活 142 / 待验 12 / 疑似 2

    日志通过 Qt Signal 自动路由，无需手动刷新。
