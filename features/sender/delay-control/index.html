    频率控制与并发策略

    B 站对弹幕发送有严格的频率限制。过快的发送会触发风控（错误码 36703: 发送频率过快），严重时可能导致账号被临时封禁。本页介绍如何配置发送延时策略，在效率和安全之间取得平衡。

    所有配置项都有对应的 UI 控件

    本页介绍的所有配置项都可以在「全局设置」页面中直接调整，无需手动编辑配置文件。每个任务也可以在「任务详情」弹窗中单独覆盖发送策略。

    基础延时（随机间隔）

    最核心的防风控设置。每条弹幕发送后，程序会等待一个随机时间再发送下一条。

    配置项 说明 默认值
    min_delay 最小等待时间（秒） 8.0
    max_delay 最大等待时间（秒） 8.5

    程序会在 [min_delay, max_delay] 区间内随机取值。例如默认配置下，每条弹幕间隔约 8.0~8.5 秒。

    关于发送间隔的硬性限制

    B 站服务器对弹幕发送有 5 秒的硬性频率限制（即两条弹幕之间至少间隔 5 秒）。考虑到网络延迟、CDN 波动等因素，程序默认设置为 8 秒左右，留出安全余量。不建议将间隔设置为 5 秒或更低，否则极大概率触发 36703: 发送频率过快 错误。

    突发模式（Burst Mode）

    模拟「连发几条后休息一会」的人工行为模式。比匀速发送更自然，适合大批量补档场景。

    工作原理

    发 → 发 → 发 ────── 长休息 ────── 发 → 发 → 发 ────── 长休息 ──────
|← burst_size →|← burst_rest →|← burst_size →|← burst_rest →|

    连续发送 burst_size 条后，进入一个较长的休息期（rest_min ~ rest_max 秒），然后继续下一轮。

    配置项

    配置项 说明 默认值
    burst_enabled 是否启用突发模式 关闭
    burst_size 每轮连发条数 3
    rest_min 休息期最小时间（秒） 40.0
    rest_max 休息期最大时间（秒） 45.0

    推荐配置

    突发模式开启、每轮 3 条、休息 30~35 秒，是比较安全且高效的组合。

    自动终止

    当发送达到指定条件时，程序会自动停止队列。适用于测试场景或分批发送。

    配置项 说明 默认值
    stop_after_count 发送 N 条后自动停止 0（不限）
    stop_after_time 运行 N 分钟后自动停止 0（不限）

    两个条件可以同时设置，任一条件先满足即触发停止。

    任务间隔

    当队列中有多个任务时，一个任务发送完毕后，程序会等待一段时间再开始下一个任务。

    配置项 说明 默认值
    delay_between_tasks 两个任务之间的等待时间（秒） 30

    ETA 预测

    发送过程中，进度条会实时显示剩余任务的预计完成时间：

    正在发送: 23 / 156 条  ████░░░░░░░░░░░░  14.7%  预计 19:32 结束

    ETA 根据当前延时设置（随机间隔 + 突发模式的动态变化）实时修正。

    防休眠

    配置项 说明 默认值
    global.prevent_sleep 任务运行时阻止系统休眠（全局，发送/监视共用） 开启

    开启后，程序会在发送期间调用系统 API 阻止 Windows 进入睡眠状态，避免长时间发送中途断开。发送结束后自动恢复正常休眠策略。

    代理设置

    配置项 说明 默认值
    global.use_system_proxy 是否使用系统代理（全局，发送/监视共用） 开启

    开启后，程序会通过 Windows 系统代理设置访问 B 站 API。如果你使用代理软件上网，保持开启即可；如果直连网络发送失败，可以尝试关闭此选项。

    完整配置示例

    min_delay: 8.0
max_delay: 8.5
burst_enabled: false
stop_after_count: 0
stop_after_time: 0

    min_delay: 8.5
max_delay: 9.5
burst_enabled: true
burst_size: 5
rest_min: 30
rest_max: 35
stop_after_count: 0
stop_after_time: 0

    min_delay: 10.0
max_delay: 12.0
burst_enabled: false
stop_after_count: 10
stop_after_time: 0
