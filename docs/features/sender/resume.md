# 断点续传与智能去重

任务跑到一半被中断（手动停止、网络断开、程序退出），重新启动队列时，**已经发出去的弹幕不会再发一遍**，剩下的照常继续。

---

## 工作原理

程序在本地数据库（`history.db`）里记着每条弹幕的发送结果。发送前会查一下数据库，看这条是不是已经发过：

```
待发送弹幕 → 生成五维指纹
                  │
                  ▼
        查询本地数据库 (history.db)
                  │
      ┌───────────┼───────────┐
      ▼                       ▼
已存在记录                 无记录
(指纹+视频匹配)              │
      │                     ▼
      ▼                  正常发送
     跳过
不消耗延时等待
```

跳过的那些条目会立刻滑过去，**不占用发送间隔**，所以中断越晚，重新启动后开头那段走得越快。

### 匹配规则（五维指纹）

程序用「五维指纹」判断两条弹幕是否完全一致，而不是只比文本：

| 维度 | 字段 | 说明 |
|:-----|:-----|:-----|
| 1 | `msg` | 弹幕文本内容 |
| 2 | `progress` | 出现时间（毫秒级精度） |
| 3 | `mode` | 弹幕模式（滚动/底部/顶部） |
| 4 | `fontsize` | 字号大小 |
| 5 | `color` | 颜色值 |

只有五维指纹完全相同，**且**目标视频（BV 号 + 分 P 的 cid）也相同，才算重复。

所以「同一时间、同一内容但样式不同」的弹幕不会被误跳过——比如一条白色滚动弹幕和一条彩色顶部弹幕是两条，都照发。

---

## 它不做什么

**不防漏发。** 这一层只挡住「已经发出去的又被发一遍」。如果你把还没发的删了、或者中途换了 XML，它不会替你补上。

**不保存队列。** 程序退出后队列本身就没有了（含进度、任务列表）。崩掉之后要把同一个 XML 重新拖进来建任务，靠上面这套查重跳过已发出的那些。真正的队列落盘与崩溃恢复在后续版本里。

**不自动重试失败的弹幕。** 失败的那几条留着，等你改好或删掉——它们可能本身就有问题，再发一遍还是失败。

---

## 有意要重发怎么办

默认情况下发过的会被跳过。确实要把同一批弹幕再发一遍时：

1. 打开「全局设置」→ 最下面的红框**危险区**
2. 勾选**允许重复发送**

之后发送前不再比对数据库，已发出的会再次发到同一个视频上，**视频里会出现重复**。用完记得关掉。

---

## 使用场景

### 场景 1：发到一半手动停止

500 条弹幕发到第 200 条时点了「停止队列」。

**操作**：直接再点「启动队列」。

**结果**：前 200 条已在数据库里，被跳过；从剩下的继续发，视频里不会出现重复。

### 场景 2：程序意外退出

发到第 200 条时程序崩了。队列不会保存，所以任务列表是空的。

**操作**：用同一个 XML 文件重新建任务，然后启动队列。

**结果**：同场景 1，已发出的 200 条被跳过。

### 场景 3：同一份 XML 又导了一次

你在某个视频上发过一批弹幕，现在又拿同一个 XML 建了新任务。

**操作**：正常启动。

**结果**：与已有记录匹配的那些会被跳过，只发没发过的。

## 查看跳过记录

发送过程中，日志面板里每条被跳过的弹幕都会单独记一行：

```
⏭️ [跳过] 已发送 (1/2): 今天天气不错
```

括号里是「本次序列里第几次出现 / 数据库里已有几条」。

任务结束时日志会打一段汇总：

```
--- 发送任务结束 ---
总计: 500 | 成功: 287 | 跳过: 200 | 失败: 13
```

---

## 未发送成功的弹幕怎么导出

跳过和失败之外，还有一批是**压根没轮到**的（你手动停了、或者到了自动停止阈值）。这些连同失败的，统称「未发送成功」。

队列跑完后，如果有未发送成功的弹幕，程序会弹窗问：

> 有 N 条未发送成功，分布在 M 个任务。要导出吗？
> 每个任务导出一个 XML，可修改后重新导入。

- **是**：选一个目录，每个任务写出一个 `{原文件名}_Unsent.xml`，只含未发送成功的那些。
- **否**：跳过导出。

导出的 XML 可以直接改好再导入建新任务。也可以在队列表格上**右键单个任务**，只导出那个任务的未发送弹幕。
